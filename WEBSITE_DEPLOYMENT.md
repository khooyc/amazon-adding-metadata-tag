# Website build and handoff

The browser edition is a static website. It has no backend, database, account system, analytics, or upload endpoint. Media processing happens in the visitor's browser.

## Build

From this project folder:

```powershell
npm install
npm run web:build
```

The complete upload-ready website is generated in `website-dist`. Upload the **contents** of that folder to the root of any static HTTPS host. Do not upload `node_modules`, the Electron application, or the rest of this project.

## Test locally

```powershell
npm run web:dev
```

Then open `http://127.0.0.1:4173`. Do not open `index.html` directly with a `file://` address because browser modules, local AI models, the service worker, and folder saving require an HTTP or HTTPS origin.

## Hosting requirements

- Serve the site over HTTPS in production.
- Preserve the directory structure inside `website-dist`.
- Serve `.mjs` files as JavaScript, `.webmanifest` as a web manifest, `.json` as JSON, `.woff2` as `font/woff2`, and `.bin` as binary data.
- Do not add a Content Security Policy that blocks same-origin scripts, workers, model files, blobs, or WebAssembly.
- The host does not need server-side code. All routes and assets are relative, so the site can also be hosted below a subdirectory.

## Supported workflow

1. Choose individual JPEG, PNG, MP4, MOV, or M4V files, choose a folder, or drag media into the browser drop zone.
2. Run the bundled local face/body detector for images only.
3. Watch each video fully before selecting it for a decision.
4. Review the automatically selected recommendations. Detection does not decide whether a person is AI-generated.
5. Tag selected media with `contains-synthetic-performer` in XMP `dc:subject`.
6. Verify the generated bytes by reading the XMP field again.
7. Download tagged copies or save them to a chosen folder in Chromium browsers.

Every output uses a `-tagged` suffix and avoids overwriting an existing output. Original files are not modified. Unsafe or unsupported video containers, TIFF, WebP, compressed PNG XMP, and extended JPEG XMP remain desktop-app workflows. The browser header's **Download desktop app** action opens the current Windows and Mac installers; it does not install the website as a PWA.

## Discovery and content handoff

The browser page includes crawlable seller-focused copy, local hero and tutorial-poster assets, social-preview metadata, and a replaceable tutorial placeholder. Before public upload, replace the placeholder video with the finished video and add a canonical URL, sitemap, robots.txt, and any structured data that accurately describes the live page. Use one stable HTTPS domain across the page, release links, and tutorial. See [docs/organic-discovery-plan.md](docs/organic-discovery-plan.md) and [docs/research/search-discovery-evidence.md](docs/research/search-discovery-evidence.md) for the content and measurement plan.
