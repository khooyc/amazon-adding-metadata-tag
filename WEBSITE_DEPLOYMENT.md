# Website build and handoff

The browser edition is a static website. It has no backend, database, account system, analytics, or upload endpoint. JPEG and PNG processing happens in the visitor's browser.

## Build

From this project folder:

```powershell
npm install
npm run web:build
```

The complete upload-ready website is generated in `website-dist`. Upload the **contents** of that folder to the root of any static HTTPS host. Do not upload `node_modules`, the Electron application, or the rest of this project.

## Test locally

```powershell
npm run web:dev
```

Then open `http://127.0.0.1:4173`. Do not open `index.html` directly with a `file://` address because browser modules, local AI models, the service worker, and folder saving require an HTTP or HTTPS origin.

## Hosting requirements

- Serve the site over HTTPS in production.
- Preserve the directory structure inside `website-dist`.
- Serve `.mjs` files as JavaScript, `.webmanifest` as a web manifest, `.json` as JSON, and `.bin` as binary data.
- Do not add a Content Security Policy that blocks same-origin scripts, workers, model files, blobs, or WebAssembly.
- The host does not need server-side code. All routes and assets are relative, so the site can also be hosted below a subdirectory.

## Supported workflow

1. Drop or choose JPEG and PNG images.
2. Run the bundled local face/body detector.
3. Review the automatically selected recommendations. Detection does not decide whether a person is AI-generated.
4. Tag selected images with `contains-synthetic-performer` in XMP `dc:subject`.
5. Verify the generated bytes by reading the XMP field again.
6. Download tagged copies or save them to a chosen folder in Chromium browsers.

Every output uses a `-tagged` suffix and avoids overwriting an existing output. Original files are not modified. TIFF, WebP, video, compressed PNG XMP, and extended JPEG XMP remain desktop-app workflows.
